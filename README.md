# Mochy Music: a free, open source music player for Android with style

Mochy is a modern music player for Android. It plays from YouTube Music and from modules, shows word by word lyrics, has a proper audio lab, imports your playlists from other apps, and can be re-skinned by anyone with a small zip file. No account needed, no ads, no tracking.

> [!WARNING]
> Mochy is still in beta, expect some bugs! Reporting them helps a lot.

📖 **Full documentation:** [mochy.fun/wiki](https://mochy.fun/wiki/), with pictures. It covers the app page by page and everything about making modules.

---

## Features

| Area | What you get |
|---|---|
| **Player** | Nine styles (Flagship, Classic, Turntable, iPod, Poster, Timeline, Lyrics, Bedside, Video), animated canvas and music video covers, swipe to skip, hold the player to change its style. |
| **Lyrics** | Word by word, asked from many sources at once and the best one kept (timed lyrics win). Switch source, nudge the timing, translate. Floating lyrics over other apps, widgets, and lyrics on the car screen. |
| **Audio lab** | Equalizer, a mixer with buses, sends and effect chains, Liveprog scripts, loudness meter, 3D sims, crossfade, and a provider order that decides where each song comes from. |
| **Library** | Local files, downloads, playlists, likes. Import from Spotify, YouTube Music, Apple Music and Tidal, every song is matched so it plays here. |
| **Stats & recap** | Listening time, top songs, artists and genres, and a "wrapped" style recap whenever you want. All on your phone. |
| **Everywhere** | Chromecast, Google TV and DLNA casting, Android Auto, a TV app, home screen widgets, "Hey Google, play … on Mochy". |
| **Backup** | Dropbox or any WebDAV server, by hand or on a schedule. Your logins never go in a backup. |
| **Modules** | Add songs, lyrics, song info, audio effects, looks, whole players, nav bars and glass with a zip. See [Modules](#modules). |
| **Privacy** | No account system, no server of ours, no analytics. GPL-3.0, read what it does. |

## Hhhh-how to install? :3

1. On your phone, open the [latest release](https://github.com/realidkroo/mochy-music/releases/latest).
2. Download the `.apk` that matches your phone. If you are not sure, pick **arm64**, that is almost every phone from the last 8 years. The **universal** one works everywhere but is bigger.
3. Open the downloaded file. Android will ask you to allow installs from your browser or file manager, say yes (you can turn it off again after).
4. Open Mochy. It walks you through a username, importing (you can skip it) and a blur check. No account needed to start listening.

Updating works the same way: install the new apk over the old one and your library stays. Mochy also tells you inside the app when there is a new one.

| Build | Use it when |
|---|---|
| **arm64** | Almost every phone. Pick this one. |
| **Universal** | You are not sure, or you use an emulator. Bigger. |
| **F-Droid flavor** | You want no self-update permission and no Play Services. |

> [!TIP]
> Only download Mochy from the releases page of this repo. A random mediafire or telegram link could be a modified app, and then your logins would not be safe, pls avoid those.

> [!NOTE]
> Mochy officially supports Android 8.0 and newer. Android 7 works unofficially.

### Update channels

| Channel | You get |
|---|---|
| **Release** | Normal GitHub releases only. |
| **Nightly** | Prereleases too (`9.0.0.2` is the second nightly after `9.0.0`), and the next release once it is newer than your nightly. |

Pick it on the version card of the Profile page.

## Where the code lives

| Path | What is in it |
|---|---|
| `app` | The Android app: Kotlin and Jetpack Compose, the player, playback service, library database, native audio engine. |
| `modules/api` | The module contract (`MochyModule.kt`), plain Kotlin with no Android in it, so a module can be built on its own. |
| `modules/bridge` | The JSON bridge that lets a module's own code run safely inside Mochy. |
| `modules/applemusic`, `monochrome`, `jiosaavn` | Built in modules, written against `:modules:api` only. |
| `providers/*` | Clients for the services Mochy talks to: InnerTube, LRCLIB, Better Lyrics, SimpMusic, Musixmatch, Genius, KuGou, Last.fm, Wikipedia, Shazam, canvas and artist video. |
| `docs` | The website and the [wiki](https://mochy.fun/wiki/), served by GitHub Pages. Longer notes on tricky parts are in `docs/notes`. |
| `tools` | Profiling scripts and audio engine tests. |

## Modules

A module adds something to Mochy. One zip with a `manifest.json` can bring any of these:

| What it adds | Example |
|---|---|
| **Songs** | A new audio source in the provider order. |
| **Lyrics** | A lyrics provider that goes first while it is on. |
| **Song info** | Facts and credits for the About song sheet. |
| **Audio effects** | Effects for the mixer. |
| **Looks** | Colours, fonts, glass, a nav bar, a mini player, whole player styles, pages, even a recreation of the app. |

One switch turns a module on or off, and off means gone everywhere. Modules run in a sandbox: a look-only zip never touches the network, and a web module only hands back JSON and stream links.

- **Making one:** start with [Your first module](https://mochy.fun/wiki/#modules-first), a whole module in two minutes.
- **Guide for module makers:** [`modules/README.md`](modules/README.md).
- **Anything about safety:** [Security & sandbox](https://mochy.fun/wiki/#modules-sandbox).

# FAQ

**Q: Is it safe to log in? (read this before signing in)**

A: You never have to log in to use this thing btw. Search, play, lyrics and downloads work without an account. Signing in is only for syncing your YouTube Music library, importing playlists from Spotify / Apple Music / Tidal, and Discord status.

**How the sign-in works**
- Mochy opens the real login page of the service (for example accounts.google.com or open.spotify.com) inside the app. You type your password into **their** page, not into a Mochy form.
- After you log in, the app keeps the session token or cookie that the service gives out, so you stay signed in. Your password is not what gets saved.
- That session stays on your phone, in the app's private storage. Mochy has no account system of its own and does not run a server that collects logins.
- The tokens are meant to be used only to talk to the service you signed in to (for example Spotify's own site to read your playlists).
- The app is open source under GPL-3.0 so you do not have to take my word for it, you can always read exactly what it does with them :)

**Q: Pls add liquid glass**

A: Not in the app itself, but it is possible as a module. See the [Liquid Glass example](https://mochy.fun/wiki/#modules-interface-example).

**Q: Monochrome/flac stream doesnt work**

A: The server is down, it's on their side, not ours. Use other available sources, and join our discord.

**Q: App too laggy, how to fix?**

A: Turning blur off, or setting it to low, helps a lot.

**Q: Animation is too slow, can you speed it up?**

A: You can speed it up on the customise page.

**Q: Can you add less spacing for the player?**

A: You can customise it yourself.

**Q: Official Desktop app?**

A: Later.

**Q: Can I contribute?**

A: Ofc! See [Contributing](#contributing).

**Q: I hate this app, I dont want to use it**

A: Nobody is forcing you to use this.

## How to build it yourself

You only need this if you want to change the code. If you just want to use the app, use the install steps above. The same guide with more detail is in the [wiki](https://mochy.fun/wiki/#build).

### What you need

- A Mac, Linux or Windows computer with a screen
- [Android Studio](https://developer.android.com/studio) (latest stable). It brings JDK 21 and the Android SDK with it
- Android SDK 36 and NDK `27.0.12077973`. Android Studio offers to download both the first time you open the project
- About 10 GB free disk space, the first build downloads a lottt
- A phone with USB debugging on, or an emulator

### Steps

```bash
git clone https://github.com/realidkroo/mochy-music.git
cd mochy-music
```

1. Open the folder in Android Studio once and let it finish syncing. This also creates `local.properties` with your SDK path.
2. Build and install on your connected phone:
   ```bash
   ./build.sh --debug -i
   ```
   First build takes a while, the next ones are much faster.
3. Or build the apk only and install it by hand. The apk lands in `apk-generated/`:
   ```bash
   ./build.sh --debug
   adb install -r apk-generated/*-debug.apk
   ```

Handy options (see `./build.sh --help` for all of them):

| Command | What it does |
|---|---|
| `./build.sh --debug -i` | Debug build, installs and opens it on your phone |
| `./build.sh --release -cc` | Release build for arm64 and universal |
| `./build.sh -fd --release` | F-Droid flavor, without the self-update permission |
| `./build.sh -n 4 --release -cc` | A nightly build (`<version>.4`) |
| `./build.sh -k` | Stops stuck Gradle builds |

Use **debug** while you are playing around, it builds much much faster. A debug build installs next to the real app, so it will not touch your normal install, but it is also a bit slower to run. Judge smoothness on a release build.

### Optional keys

Mochy builds fine without these, only the matching feature is switched off. Put them in `local.properties` (it is never committed):

```properties
LASTFM_API_KEY=...
LASTFM_SECRET=...
DISCORD_CLIENT_ID=...
```

Never commit your keys. Libre.fm works without any key.

### Check your change

```bash
./gradlew :app:compileArm64FossDebugKotlin   # does it compile?
./gradlew testDebugUnitTest                  # unit tests
```

### If the build fails

- `Unresolved reference` or Hilt errors that make no sense: delete the `build/` folders and `.gradle/` and build again.
- Stuck or weird Gradle: `./build.sh -k`, then try again.
- Wrong Java: make sure Gradle uses JDK 21 (Android Studio → Settings → Build Tools → Gradle → Gradle JDK).
- Still stuck? Open an [issue](https://github.com/realidkroo/mochy-music/issues) with the error text.

## Contributing

Want to send a fix? Read [CONTRIBUTING](.github/CONTRIBUTING.md) first. The short version:

1. Fork, make a short branch, keep one fix or feature per pull request.
2. Match the code around you, and guard newer Android APIs with `SDK_INT` (Mochy supports Android 8+).
3. Don't trade a feature or animation for speed. Show before/after screenshots for UI changes.
4. Test it on a device, then open the pull request.

> [!NOTE]
> AI written code is fine, blind AI slop is not. Read it, run it and understand it before you send it.

Found a bug? Report it on [issues](https://github.com/realidkroo/mochy-music/issues) with your Mochy version, Android version, device, and what happened. Logs (`adb logcat`) and a screenshot help a lot.
